# 事实源与暂停规则

## 唯一允许的事实来源

- 前端页面代码
- 前端交互效果
- api 定义
- mock 数据或接口
- 接口数据类型和格式
- 已提交的模块规格文档
- 现有后端代码中可直接复用且可证明相关的模式
- 用户明确确认的信息

## 零猜测规则

以下结论如果不能被事实源直接支撑，就不能写进规格，也不能写进实现：

- 请求字段语义
- 返回字段语义
- 字段是否必填
- 状态值语义
- 状态流转规则
- 数据库主从关系或存储关系
- 唯一约束
- 编号规则
- 校验阈值
- 打印模板或文件模板规则
- 外部依赖或设备交互细节

## 模块边界

- 新模块必须由用户手动指定模块目录后才能开始。
- 不能自己扫描并决定做哪个模块。
- 每次只允许一个模块处于活跃开发状态。

## 必须暂停的情况

命中任一项时，立即停止并向用户确认：

- 无法证明某项结论的事实来源
- 前端页面、交互效果、api 定义、mock 之间存在冲突
- 无法判断字段含义
- 无法判断字段是否必填
- 无法判断状态值语义
- 无法判断数据库关系
- 无法判断状态流转规则
- 编号规则不明确
- 生物识别或上传结构不明确
- 打印模板或文件模板规则不明确
- 外部依赖或设备交互不明确
- 测试失败但无法确认是代码问题还是环境问题
- 服务无法启动且无法自动恢复
- 本地端口不可访问且无法自动恢复

## 向用户提问时必须带上的信息

- 当前模块
- 当前阶段：`spec` 或 `backend_dev`
- 当前任务
- 已确认的事实依据
- 无法继续推进的原因
- 需要用户明确回答的问题列表
